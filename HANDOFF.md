# v0.15: adaptive feedback and control room

The key gap was progress evaluation: a movement acknowledgement could look productive even when the bot circled locally. Another gap was calibration: a channel with two noisy samples could be considered sampled yet remain unusable by the inverse model.

Changes: adaptive_feedback tracks a bounded two-minute position window and detects local repetition after a minute without measured productive work. Outcomes carry explicit engineered components for newly visited areas, verified supplied task steps, need reduction, failed attempts and repeated-area movement. Feedback applies a bounded adjustment to routine priority; failure-specific cooldowns also increase. This is outcome-guided heuristics, not reinforcement-learning model training or emotion. Rewards are imperfect proxies, not proof that a human goal was fulfilled.

Recovery alternates among available measured yaw, pitch, forward/back and sideways effects when local repetition is detected; safe body checks still apply. No channel meanings were inserted into the learner. Uncertain sampled movement channels receive bounded resampling (up to 12 samples). Exploration favors less-visited cells. Supplied navigation allows drops of up to two blocks rather than one, while retaining hazard exclusions, cardinal paths, and progress deadlines.

The dashboard at http://127.0.0.1:8765/ now has Start, Pause, goal editing and assisted-routine/learning toggles. It needs the launcher running; Start resumes the bot, not the server process. Commands use a bounded expiring local mailbox and enter the existing session/action path. Same-origin JSON and a custom header protect the control endpoint from ordinary cross-site form submissions. Read endpoints remain read-only.

Both dashboard and http://127.0.0.1:8765/overlay show six schematic activity regions. Flashes correspond to changed module-event records, not invented thought or biological anatomy. OBS may need its Browser Source refreshed. The original Downloads HTML was updated, but the hosted overlay remains preferred.

Validation: 100 Python tests, 25 Node tests. Replay of 180 saved observations detected the real local loop (8.5-block extent). A single short installed-server check verified GUI pause/resume, no module delivery failures, movement out of the prior plateau, and new-area feedback. No second Minecraft server was started. No long-duration claim. World, identity and learned history preserved; code backup is in the installation's backups directory.

Remaining work: validate recovery over longer sessions; distinguish repeated legitimate building work from stagnation more precisely; develop explicit multi-step goal completion criteria and context-dependent skill selection. Current novelty memory is bounded and task-step rewards are supplied definitions. The SQLite evidence database continues to grow; retention/archival needs its own measured design. The current brain diagram groups software activity rather than reproducing brain structure.
